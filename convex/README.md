# Community backend

The game calls `POST https://different-ostrich-580.convex.site/community`. The `.site` URL serves HTTP actions; the `.cloud` URL identifies the deployment used by the Convex CLI. The endpoint supports browser CORS preflights. [Convex HTTP action documentation](https://docs.convex.dev/functions/http-actions).

Install Node.js 24 or later and run `npm ci` from the repository root. Authenticate with an account that has access to the existing project, then run `npm run convex:deploy`. The included `convex.env` explicitly selects **different-ostrich-580**, the development deployment supplied for this game. `npm run convex:dev` watches and updates the same deployment. Keep credentials out of source control and Web exports.

The HTTP actions and schema are deployed to the supplied deployment. Publishing, voting, listing levels and replays use that backend. It had no existing tables before this feature was installed.

The schema stores levels, revision-scoped votes, replays, and capability-based write limits, including a five-minute personal publishing cooldown shared by new levels and edits. Only successful publications start the cooldown; failed attempts leave its deadline unchanged. The HTTP endpoint returns status 429 with `publish_cooldown`, `retryAfterMs`, and `nextPublishAt` for early attempts. Listing levels also returns the remaining personal cooldown so the client can restore it across sessions. The browser generates a 256-bit ownership token and stores it in a first-party `Secure; SameSite=Lax` cookie and persistent Godot user storage. Only its SHA-256 hash is stored on the server. The list response omits ownership hashes and returns only the caller's owned IDs. Clearing both the cookie and site storage loses ownership; this intentionally has no account recovery. Cookies identify a browser, not a verified person, so votes are one per browser identity rather than one per human.

Level list responses include a replay count. New uploads and owner-authorized replay deletions update this counter atomically, while duplicate uploads and repeated deletions leave it unchanged. Older level records without the optional counter derive their count from their existing replays until the next new replay populates the counter. Republishing resets the replay count and removes earlier revisions' votes and replays. Replay queries immediately show only the current revision; indexed cleanup removes old rows in bounded batches without touching newer activity. Replay lists return a caller-specific `owned` boolean without exposing ownership hashes. `deleteReplay` checks the capability on the server and removes only that replay.

Level metadata is included inside its portable encrypted string and indexed separately for listing. The server decrypts each upload, validates dimensions and tiles, and replays a completion proof using the game's crossing rules. Edits require the ownership token and the expected revision. They reset votes and remove previous-version replays after the client asks for confirmation. Deletion removes related votes and replays in scheduled batches. Replay uploads are validated, deduplicated, and tied to an exact revision.

Hot uses Reddit's original formula: `sign(up-down) * log10(max(abs(up-down),1)) + (createdSeconds-1134028003)/45000`. Other filters rank by net votes among puzzles created in the last 24 hours, 7 days, 30 days, 365 days, or all time. Results and replay lists are paginated. Search matches the level name or author case insensitively. The client automatically passes pages without matches; More continues through the remaining ranked matches.

`HL1.` strings contain dimensions, RGB color, UTF-8 name and author, and two-bit tile values. `HR1.` replay strings contain only variable-length input actions and delta milliseconds; gaps over five seconds are capped. Both use gzip/DEFLATE followed by AES-256-CBC with a random IV and base64url. The portable key is part of the client format; encryption does not authenticate an owner or hide public puzzles. Ownership is enforced separately on the server. Inflate sizes, event counts, metadata lengths and move legality are bounded.

Run `npm test` for codec and Convex backend tests, and `npm run typecheck` for TypeScript checks. The tracked fixture was generated by Godot; running `tests/test_community.gd` creates a fresh interoperability fixture that the Node tests prefer automatically. The Convex tests use an isolated in-memory backend and do not upload test content to the live deployment.
